# Contributing

Bug reports, method implementations and benchmark critiques are all welcome.

## Setup

```bash
git clone https://github.com/echosumeet/demand-forecast-lab
cd demand-forecast-lab
python -m pip install -e .
make test
```

## Ground rules

1. **Tests are stdlib `unittest`.** No pytest-only fixtures or decorators.
   Written as plain `unittest`, the suite still runs under pytest for anyone
   who has it.
2. **No new runtime dependencies** beyond numpy, scipy, scikit-learn and
   matplotlib. If a method needs something else, implement the recursion.
3. **Every number in the README comes from `benchmarks/run_benchmarks.py`.**
   If a change moves the results, re-run it and commit the regenerated
   `benchmarks/results.md` and figures in the same commit.
4. **All data is generated by `dflab.datagen`.** No scraped or third-party
   datasets, ever.

## Adding a forecasting method

- Local methods subclass `dflab.base.BaseLocalForecaster` and implement
  `_fit()` and `_predict(h)`. Populate `self._fitted` with genuine one-step
  ahead in-sample predictions -- reconciliation and scale estimation depend on
  them, and a fitted value that peeks at its own observation will silently
  flatter the method.
- Cross-learning methods implement `fit_panel(P) / predict_panel(h)` and set
  `is_global = True`.
- Cite the paper in the class docstring, and add a test that asserts a
  *property* from that paper, not just that the code runs. The existing
  examples: SBA is Croston deflated by `1 - alpha/2`; TSB decays on a
  discontinued item while Croston freezes; every reconciliation method
  satisfies `S G S = S`.

## Adding a metric

Handle the zero-actual case explicitly and say what you chose in the
docstring. Returning `inf`, `nan` or `0` are all defensible; picking one by
accident is not.
